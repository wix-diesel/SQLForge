# クエリ実行とテーブル編集

## クエリを実行する

ツリーのテーブルかデータベースを右クリック → メニューの項目で作業領域が開く。
「クエリを実行」「新しいクエリ」で開くのは**空のエディタ**で、決まるのは実行先のデータベースだけ。
テーブルの「先頭 1000 件を表示」（SSMS の「上位 1000 行の選択」にあたる）は、
`SELECT TOP (1000) * FROM [dbo].[orders];` を組み立てて開くと同時に実行する。

開く操作はどれも**タブを 1 枚足す**（[タブ](#タブ)を参照）。前に開いたクエリは畳まれずに残る。

実行するとエンジンへ文面をそのまま送る。分割も書き換えもしないので、複数の文をまとめて投げられる。
結果セットが複数返れば「結果 1」「結果 2」…とタブが並び、行を返さない文の件数と実行時間は「メッセージ」に出る。

| ふるまい | 中身 |
| --- | --- |
| 実行先のデータベース | 実行の直前に `USE [db]` で合わせる。エディタの文面は修飾なしで書かれるのが普通なため |
| 書き込み | 止めない。`INSERT` も DDL もそのまま送る |
| 取得上限 | 結果セットごとに 1,000 行で打ち切る。打ち切ったことは結果ペインとメッセージに出す（黙って切らない） |
| 取り消し | ツールバーの「停止」。`CancellationToken` がそのままドライバーへ渡る |
| 値の見せ方 | 不変カルチャで文字列へ写す。NULL は薄字の `NULL`（`'NULL'` という値と見分けられるように区別して持つ） |
| 同時実行 | カタログの照会と同じ門を通す。ツリーを展開しながら実行しても接続を取り合わない |

**接続の「読み取り専用」は印であって、書き込みを止める仕掛けではない**（`AccessMode.ReadOnly`）。
一覧とステータスバーに盾のアイコンを出すだけで、文面は素通しする。文面から書き込みかどうかを
見分ける仕掛けは動的 SQL のような形をどうせ通してしまい、あると「止まるはず」という誤解を招くので、
止めるのはサーバー側の権限の仕事にしてある。書かせたくない接続には読み取り専用のロールを与えること。

## タブ

エディタの上にタブ帯があり、**タブ 1 枚が SSMS のクエリ ウィンドウ 1 つ**にあたる。
文面・実行先のデータベース・実行の状態・結果ペイン（「結果 1」…「メッセージ」）は、
どれもタブごとに持つ。隣のタブが実行していても、こちらの結果や見出しは巻き添えにならない。

| ふるまい | 中身 |
| --- | --- |
| タブが増える入口 | ツリーの「新しいクエリ」「クエリを実行」「先頭 1000 件を表示」、ストアドの「実行」、ツールバーの「新しいクエリ」（Ctrl+N） |
| 見出し | `SQLQuery1.sql` から始まる連番。閉じても番号は使い回さない（SSMS と同じ） |
| 変更の印 | 一度でも打ち込んだら見出しの後ろに `*` を添える。保存の口はまだ無いので、付いた `*` は消えない |
| 実行先 | タブごとに持つ。ツールバーの「新しいクエリ」は今のタブと同じ実行先で開く（タブが無ければ接続時のデータベース） |
| 閉じる | タブの `×`・中クリック・Ctrl+F4・ツールバー右端の `×`。右クリックのメニューに「これ以外をすべて閉じる」「すべて閉じる」 |
| 閉じたあとどれが前に出るか | **隣ではなく直前に見ていたタブ**（SSMS と同じ） |
| 実行中に閉じたとき | その実行を取り消す。結果を出す先が無くなるため |
| 行き来 | Ctrl+Tab で次、Ctrl+Shift+Tab で前。端まで来たら反対の端へ回る |
| 書きかけの位置 | タブごとに覚えていて、戻ってくるとそこへ帰る |
| 最後の 1 枚を閉じたとき | 作業領域ごと畳む（ツリーの選択の概要に戻る） |

**保存の口はまだ無い。**閉じるときに確認もしない（SSMS は保存を尋ねる）。ファイルへの保存を
実装する時点で、そこに合わせて確認を足す。

エディタ（`TextEditor`）は 1 つを使い回し、タブを切り替えるたびに文書（`TextDocument`）を
差し替える。タブごとに `TextEditor` を作ると、色分け・補完・キー割り当ての配線が
タブの枚数ぶん増えるため。

## エディタ（色分け・補完・整形）

エディタは `AvaloniaEdit` の `TextEditor`。文面の読み取りは自前の字句解析器
（`SQLForge.Domain/Sql/SqlLexer.cs`）が 1 本で受け持ち、**色分け・補完・整形の 3 つが同じ字句を見る**。
同じ文面を 2 通りに解釈する実装が並ぶと必ず食い違うため、解析はここへ寄せてある。

| ふるまい | 中身 |
| --- | --- |
| 色分け | 字句の種類ごとに `Themes/Tokens.axaml` の `Syntax*Brush` を当てる。色はテーマのトークンから引くので、ライト・ダークの切り替えにそのまま追従する |
| 補完を出す条件 | 語を打ち始めたときと `.` を打ったとき。文字列とコメントの中では出さない |
| 補完の中身 | `FROM` / `JOIN` の後ろはスキーマとテーブル、`SELECT` / `WHERE` / `ON` の中は列と予約語、`dbo.` の後ろはそのスキーマのテーブル、`o.` の後ろは別名 `o` が指すテーブルの列 |
| 別名の解決 | 今の文（`;` と `GO` で区切る）の `FROM` / `JOIN` を読んで「別名 → テーブル」を作る。前の文のテーブルは混ざらない |
| カタログの読み込み | 接続 1 本につき 1 つの覚え書き（`SchemaCache`）に貯める。1 文字打つたびにサーバーへ行かない |
| 差し込む文字列 | そのままでは識別子として通らない名前（空白を含む・予約語と同じなど）にだけ `[ ]` を付ける |
| 整形 | ツールバーの「整形」か Ctrl+Shift+F。句ごとに改行し、予約語だけを大文字へ揃える |

**整形は見た目だけを変える。**字句を並べ直すだけなので、次の 2 つが必ず成り立つ
（`SqlFormatterTests` が見本ごとに機械的に確かめている）。

- 空白と予約語の大小のほかは、字句の並びが変わらない（増やさない・減らさない・つなげない）。
- 2 回かけても結果が変わらない。

文字列とコメントの中身は触らない。行コメント（`--`）の後ろには必ず改行を入れる（入れないと
後ろの文がコメントに飲まれるため）。`GO` も必ず 1 行に独立させる。識別子は照合順序によっては
大小を区別するので、大文字にするのは予約語だけにしてある。

語彙（予約語・組み込み関数・型名）は今のところ T-SQL のものだけを持つ。2 つ目のドライバーを
実装する時点で、ドライバーごとの表に分ける。

## テーブルの先頭 100 行を編集する

ツリーのテーブルを右クリック → 「先頭 100 行を編集」で編集グリッドが開く（SSMS の
「上位 200 行の編集」にあたる。行数は 100 にしてある）。編集グリッドは作業領域に 1 つだけで、
開いている間はクエリエディタ（タブ帯ごと）が引っ込み、閉じると開いていたタブがそのまま戻ってくる。

セルを押すと入力欄になり、Enter・Tab・ほかを押して離れると確定する。Esc で打ちかけを捨てる。
確定した時点で、変わった 1 セルだけが `UPDATE` で書き戻る（保存ボタンは無い。SSMS と同じ）。

| ふるまい | 中身 |
| --- | --- |
| 行の特定 | 主キーの変更前の値を `WHERE` に置く。主キーが無いテーブルでは、比較できる列すべてを並べる（SSMS と同じ） |
| 当たった行が 1 行でないとき | 更新はトランザクションごと取り消す。0 行なら「読み直してください」、2 行以上なら当たった数を出す |
| 書き換えられない列 | IDENTITY・計算列・rowversion と、グリッドで扱えない型（binary・xml・text・空間型）。薄字で出して押しても開かない |
| 空欄の確定 | 文字列の列なら空文字列、それ以外なら NULL。NULL を入れるのは Ctrl+0（と右クリックのメニュー）だけ |
| 値の型 | 表示の文字列を列の型へ写してからパラメータで渡す。読めない文字列はサーバーへ送る前に弾く |
| 失敗したとき | 表示は元の値のまま残し、理由をツールバーの右へ出す（画面とサーバーが食い違わないように） |
| 読み取り専用の接続 | セルを開かせない。クエリの実行とは違い、こちらは押した操作がそのまま書き込みになるため |

### 行の追加と削除

グリッドのいちばん下には、行番号が `*` の新しい行が常にある（SSMS と同じ）。そこへ打ち込んで
Enter を押すと 1 行が足される。Tab は隣のセルへ移るだけで、行はまだ送らない。Esc（と行の
右クリック → 「新しい行を取り消す」）で打ちかけを捨てる。

削除は行の右クリック → 「行の削除」。取り消せないので必ず一度尋ねる。

| ふるまい | 中身 |
| --- | --- |
| 追加で送る列 | 打ち込んだ列だけ。触っていない列は文面に出さず、既定値（DEFAULT 制約）に任せる（SSMS と同じ） |
| 追加できない列 | IDENTITY・計算列・グリッドで扱えない型。新しい行でも押しても開かない |
| 足したあとの値 | 同じ文面の中で足した行を読み直し、サーバーが決めた値を画面へ写す（IDENTITY は `SCOPE_IDENTITY()` で当てる）。当てにいけない鍵のときはグリッドごと読み直す |
| 足すのに失敗したとき | 打ちかけは残したまま理由だけを出す。直してもう一度確定できる |
| 削除の条件 | 書き換えと同じ組み方（主キーの値、無ければ比較できる列すべて）。当たった行が 1 行でなければトランザクションごと取り消す |
| 主キーが無いテーブル | 行は足せるが、消せない・書き換えられない（どの行かを決められないため） |
| 読み取り専用の接続 | `*` の行を出さない。削除のメニューも出ない |
