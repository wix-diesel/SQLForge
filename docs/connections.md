# 接続

## SQL Server へ繋ぐ

ダイアログの「新しい接続」は SQL Server が既定になっている。ホスト・ポート（既定 1433）・
データベース・ユーザー・パスワードを入れて「接続をテスト」か「接続」を押す。

TLS の要求レベルは接続文字列へこう写す。

| 「一般」タブの TLS | SSMS の [暗号化] | SqlClient | 意味 |
| --- | --- | --- | --- |
| 使用しない / 可能なら使用 | Optional | `Encrypt=Optional`, `TrustServerCertificate=true` | クライアントからは必須にしない（サーバーが要求すれば張られる） |
| 必須 | Mandatory + 証明書を信頼する | `Encrypt=Mandatory`, `TrustServerCertificate=true` | 暗号化は必須。証明書は検証しない |
| 必須 + 証明書検証 | Mandatory | `Encrypt=Mandatory`, `TrustServerCertificate=false` | 暗号化必須かつ証明書を検証する |
| 厳密 (TDS 8.0) | Strict | `Encrypt=Strict` | 最初から TLS を張る。証明書は必ず検証する（SQL Server 2022 / Azure SQL 以降） |

SSMS は［暗号化］と［サーバー証明書を信頼する］の 2 つで同じことを決めるが、SQLForge では
組み合わせを 1 本の並びに畳んである。同じことを 2 か所で決めると、どちらが効いているのか
分からなくなるため。

接続テストの結果に出る「TLS 有効 / なし」は、要求した設定ではなくサーバーに問い合わせた実際の状態
（`sys.dm_exec_connections`）。この DMV は `VIEW SERVER STATE` 権限が要るので、読めない接続では
「TLS 不明 (要求 …)」と出して推測しない。

## PostgreSQL へ繋ぐ

ドライバーを **PostgreSQL** に切り替えると、ポートとデータベースの既定が
5432 / `postgres` に変わる。入れる欄は SQL Server と同じで、
「接続をテスト」「接続」の押し方も変わらない。

繋がると、ツリーには接続と**データベース一覧**が並ぶ。データベースを開けば
スキーマ・テーブル・列・ストアド プロシージャ（関数を含む）まで辿れる。
この版ではそこまでで、セキュリティ（ログイン・ユーザー・ロール・権限）と
編集グリッドはまだ書いていないので、**枝も右クリックのメニューも出ない**
（押してから断られないように、セッションが自分でできることを申告している）。

SQL Server と違うところ。

| | SQL Server | PostgreSQL |
| --- | --- | --- |
| ドライバー | `Microsoft.Data.SqlClient` | `Npgsql` |
| 繋ぎ先の書き方 | `Data Source=host,port` | `Host=host` と `Port=port` の 2 欄 |
| 他のデータベースを読む | 3 部名（`[db].sys.tables`）で 1 本の接続のまま | またげないので、読む前にそのデータベースへ**接続を張り直す** |
| データベースの作成日時 | `sys.databases.create_date` | 相当する列が無いので「読めない」扱い（ツリーの作成日での絞り込みも掛からない） |
| 暗号化の確認 | `sys.dm_exec_connections`（`VIEW SERVER STATE` が要る） | `pg_stat_ssl` の自分の行 |

TLS の要求レベルは libpq の `sslmode` へこう写す。

| 「一般」タブの TLS | Npgsql | 意味 |
| --- | --- | --- |
| 使用しない | `SslMode=Disable` | 暗号化しない。サーバーが要求すれば繋がらない |
| 可能なら使用 | `SslMode=Prefer` | 張れるなら張る |
| 必須 | `SslMode=Require` | 暗号化は必須。証明書は検証しない |
| 必須 + 証明書検証 | `SslMode=VerifyFull` | 暗号化必須かつ証明書とホスト名を検証する |
| 厳密 (TDS 8.0) | `SslMode=VerifyFull`, `SslNegotiation=Direct` | 接続直後に TLS を張る（PostgreSQL 17 以降）。SQL Server の TDS 8.0 に当たる |

「TLS / SSL」タブのサーバー証明書は `sslrootcert`（Npgsql の `Root Certificate`）へ写す。
**証明書内のホスト名は写せない**（Npgsql に相当する指定が無い）ので、入れたまま繋ごうとすると、
検証が通ったように見せずに接続する前に断る。

認証は、パスワード認証がそのまま `Username` / `Password`。**OS 統合認証**は、Npgsql に
「統合認証を使う」という指定が無いので、利用者名もパスワードも載せずに繋ぐ
（名乗る相手は OS が決め、サーバーが求めたときに GSSAPI / SSPI で応じる）。
クライアント証明書認証は SQL Server と同じく未対応。

「詳細設定」タブのうち、ネットワーク プロトコルとパケット サイズは PostgreSQL に相当する指定が
無いので効かない。接続と実行のタイムアウトは効く（接続のほうは Npgsql の上限 1024 秒で頭打ち）。

## OS 統合認証（Windows 認証）で繋ぐ

「一般」タブの認証方式で **OS 統合認証** を選ぶと、SQL Server へは
`Integrated Security=true` で繋ぐ。名乗る相手を決めるのは OS なので、
利用者名もパスワードも接続文字列には載らない。

そのぶんダイアログの見え方も変わる。

| 認証方式 | 「一般」タブに出るもの |
| --- | --- |
| パスワード | ユーザーの入力欄と、パスワードの入力欄（キーリングへ預けるトグル付き） |
| OS 統合認証 | 打てる欄の代わりに、**実際に名乗る OS アカウント名**を読み取り専用で表示 |

打てる欄を残さないのは、打った値が使われないため。ユーザー欄に何か入っていても、
統合認証を選んだ時点でその値は保存内容にも接続 URL にも残らない
（`ConnectionCredentials` が落とす）。同じ理由でパスワードもキーリングへ預けない。

出る OS アカウント名は OS ごとに違う。

| OS | 名乗るアカウント | Kerberos の下ごしらえ |
| --- | --- | --- |
| Windows | `WindowsIdentity.GetCurrent().Name`（`DOMAIN\user` の形） | 要らない。OS の資格情報がそのまま渡る |
| Linux / macOS | ログイン名（`Environment.UserName`） | 要る。`kinit` で資格情報を取っておく |

Kerberos の用意が要る OS では、統合認証を選ぶとその旨をダイアログに出す。
それでも整っていなければ接続時に SqlClient が理由を返すので、フッターにそのまま出る。

確認用の接続 URL にも認証方式が出る。統合認証には権限部に書ける利用者名が無いので、
代わりにクエリへ `integrated_security=true` を足す。

```
パスワード認証: sqlserver://analyst_ro@db.internal:1433/sales_db?sslmode=require&application_name=sqlforge
OS 統合認証:    sqlserver://db.internal:1433/sales_db?sslmode=require&integrated_security=true&application_name=sqlforge
```

## SSH の踏み台ごしに繋ぐ

「SSH トンネル」タブでトグルを入れると、踏み台へ繋いでから DB へ行く。手元の 127.0.0.1 に
待ち受け口を 1 つ開き、そこへ来たものを踏み台ごしに「一般」タブの繋ぎ先へ流す。

| 欄 | 中身 |
| --- | --- |
| 踏み台のホスト / ポート | 既定は 22 |
| 踏み台の利用者名 | 踏み台へ名乗る名前。DB の利用者名とは別 |
| 認証方式 | パスワード / 秘密鍵 |
| 秘密鍵 | 鍵のファイル。先頭の `~` はホームとして扱う |
| パスワード（パスフレーズ） | パスワード認証ならパスワード、秘密鍵ならパスフレーズ。DB のパスワードと同じくキーリングへ預けられる |
| 手元のポート | 空欄なら空いているポートを自動で選ぶ |

**待ち受けは 127.0.0.1 にだけ開く。**`0.0.0.0` に開くと、同じ網にいる誰でもこの機械ごしに
踏み台の向こうへ入れてしまうため。

トンネルは接続と寿命をそろえてある。接続が開けばセッションと一緒に閉じ、開かなければ
その場で閉じる。「接続をテスト」で開いたぶんもテストの中で閉じる。

**繋ぎ先が 127.0.0.1 になるので、TLS の証明書の名前は合わなくなる。**証明書はサーバーの
本来の名前で出ているので、証明書を検証する設定（必須 + 証明書検証 / 厳密）で繋ぐときは、
「TLS / SSL」タブの［証明書内のホスト名］にその名前を入れる。

**SSMS にこのタブは無い。**踏み台の指定の並びは SQLForge のもので、パスワードとパスフレーズの
預け方だけ「一般」タブと同じにしてある（キーリングの鍵は `sqlforge:<接続の Id>:ssh`）。

**既知ホストの台帳（`known_hosts`）は持たない。**持たない以上「知っている鍵か」を判断できないので、
繋いだうえでホスト鍵の指紋を接続テストの結果に出す。

```
接続に成功  PostgreSQL 16.2 · TLS 有効 · 往復 42 ms · SSH alice@bastion.internal:22 · ホスト鍵 SHA256:ohD8VZ…
```

## TLS の証明書を指定する

「TLS / SSL」タブは、要求レベル（「一般」タブ）を**検証するときの材料**だけを持つ。
SSMS の［Host Name in Certificate］と［サーバー証明書］に当たる。

| 欄 | SqlClient | 使いどころ |
| --- | --- | --- |
| 証明書内のホスト名 | `HostNameInCertificate` | 繋ぎに行く名前と証明書の CN / SAN が食い違うとき。SSH トンネルごしでは必ず要る |
| サーバー証明書 | `ServerCertificate` | 社内の認証局を OS の信頼ストアへ入れずに、この 1 枚とだけ突き合わせたいとき |

証明書を検証しない要求レベル（使用しない / 可能なら使用 / 必須）のときは、指定してあっても
使われない。保存はするが、効かないことはタブの中に出す。

## 詳細設定

「詳細設定」タブは SSMS の［接続プロパティ］と［追加の接続パラメーター］にそろえてある。
既定値も SSMS と同じ。

| 欄 | 既定 | SqlClient |
| --- | --- | --- |
| ネットワーク プロトコル | &lt;既定値&gt; | データ ソースの接頭辞（`tcp:` / `np:` / `lpc:`） |
| ネットワーク パケット サイズ | 4096 バイト | `Packet Size` |
| 接続タイムアウト | 15 秒 | `Connect Timeout` |
| 実行タイムアウト | 0 秒（待ち続ける） | `Command Timeout` |
| 追加の接続パラメーター | 空 | 書いたものをそのまま接続文字列へ |

追加の接続パラメーターは `キー=値;` の並びで、組み立てた接続文字列の**最後に**写す。
SSMS と同じで、ここに書いたものが他のタブの指定より優先される。読めないキーは接続を
試みる前に理由が出る。SSMS の［Always Encrypted］タブに当たる設定（`Column Encryption
Setting` など）も、専用の欄は持たないぶんここから渡せる。

実行タイムアウトを 0 にすると、走っている文面はこちらからは止まらない。そのため接続を
解除するときは 5 秒だけ待ち、終わらなければ接続ごと切る（閉じられずに残るほうが困るため）。

**ここに書いた値は接続情報のファイルにそのまま残る。**キーリングを通らないので、
パスワードの類は書かないこと。ダイアログにもその旨を出している。

## 接続情報を保存する

「保存」を押すと、接続情報は OS の設定ディレクトリの `connections.toml` に残る。
次の起動でも左ペインに並び、**行を押すとその接続で繋ぎに行く**。

| OS | 接続情報 (TOML) | パスワードの預け先 |
| --- | --- | --- |
| Linux | `~/.config/sqlforge/connections.toml`（本人だけが読める 0600） | Secret Service（`secret-tool` ごし。GNOME キーリング / KWallet など） |
| Windows | `%APPDATA%\sqlforge\connections.toml` | 資格情報マネージャーの汎用資格情報（`sqlforge:<接続の Id>`） |
| macOS | OS の設定ディレクトリの `sqlforge/connections.toml` | ログイン キーチェーンの汎用パスワード（項目名 `sqlforge`） |

**パスワードは TOML には書かない。**ファイルに残るのは「どこへ誰として繋ぐか」までで、
パスワードは `ISecretStore` の OS ごとの実装が OS のキーリングへ預ける。SQLForge 自身は
暗号鍵を持たない — 暗号化と、取り出してよい相手かの判断は OS の担当にしてある。

キーリングを使えない環境（`secret-tool` が入っていない、セッション バスが無い、など）では
「キーリングを利用できません」と出して保存トグルを無効にする。パスワードは都度入力になるが、
接続情報そのものの保存は使える。

左ペインの行を押したときの動きは次のとおり。

| 状態 | 押したとき |
| --- | --- |
| パスワードを預けてある / OS 統合認証 | そのまま接続して、メインウィンドウが開く |
| パスワードが要るのに預けていない | 入力欄へ写して「パスワードが必要です」と出す（サーバーへは行かない） |
| 入力欄にパスワードを打ってある | 打った値で接続する（預けてあるものより優先する） |

キーボードでの上下移動や、起動直後に先頭が選ばれることでは繋ぎに行かない。
押した操作だけを合図にしてあるのは、開くつもりのない接続—とくに本番—へ
うっかり繋いでしまわないようにするため。

### 保存済み接続を消す・持ち運ぶ

SSMS の「登録済みサーバー」と同じ操作をそろえてある。

| 操作 | 出し方 | すること |
| --- | --- | --- |
| 削除 | 行の右クリック → 「削除」 | 確認のうえ、`connections.toml` の 1 件と、預けてあるパスワードの両方を消す |
| 書き出し（1 件） | 行の右クリック → 「書き出し…」 | その接続だけを 1 枚のファイルへ書く |
| 書き出し（全件） | フッターの ↑ ボタン | 保存済みのすべてを 1 枚のファイルへ書く |
| 取り込み | フッターの ↓ ボタン | 書き出したファイルを読んで保存済み接続へ足す |

書き出しダイアログでは、SSMS と同じく**「ユーザー名とパスワードを書き出さない」**を選べる。

| 選択 | ファイルに入るもの |
| --- | --- |
| 書き出さない（既定） | 繋ぎ先（ホスト・ポート・データベース・TLS・環境タグ・アクセス種別）だけ。利用者名は空で書く |
| 書き出す | 上に加えて利用者名と、キーリングに預けてあるパスワード |

SSH トンネルと TLS の証明書と詳細設定は、どちらを選んでも**繋ぎ先の一部として書き出される**
（踏み台のホスト・利用者名・鍵の置き場所など）。ただし**踏み台のパスワードとパスフレーズは
どちらを選んでも書き出さない**。持ち出す先で入れ直すことになる。

取り込みで手元の接続に当たったときは、SSMS と同じ 5 択（置き換える / すべて置き換える /
飛ばす / すべて飛ばす / キャンセル）を 1 件ずつ尋ねる。「同じ接続」の見方は、
まず Id、無ければ**同じ環境タグの同じ名前**（大文字小文字は区別しない）。
名前が同じでも環境タグが違えば別の接続として足す。キャンセルすると 1 件も書かない。

書き出したファイルはふだんの保存先と同じ TOML の形なので、そのまま `connections.toml` として
置くこともできる。パスワードを含めていてもいなくても、置き場所を選んだ時点で
本人だけが読める権限（Unix の 0600）にする。

**SSMS との違いが 1 点ある。**SSMS は書き出したパスワードを Windows の利用者・機器に
結びつけて暗号化するが、SQLForge は暗号鍵を持たない（暗号化は OS のキーリングの担当にしてある）。
そのため「書き出す」を選んだファイルには、パスワードが**そのまま読める形**で入る。
ダイアログでもその旨を出す。既定で含めないのはこのため。
