# 現在の状態

**フェーズ 1 のうち、接続ダイアログ・オブジェクトエクスプローラー・クエリ実行・テーブルの編集**が動く。

アプリを起動すると接続ダイアログが開く。保存済み接続の一覧・検索、接続情報の入力と検証、
環境タグ、読み取り専用モードのトグル、接続 URL の組み立てまでが動く。

**接続情報は保存して使い回せる。**「保存」を押すと OS の設定ディレクトリの
`connections.toml` に残り、次の起動でも左ペインに並ぶ。**左ペインの行を押すと、
その接続でそのまま繋ぎに行く**（パスワードは OS のキーリングから取り出す）。
パスワードを預けていない接続では、繋ぐ前に入力を促す。

**保存済み接続は消したり持ち運んだりできる。**SSMS の「登録済みサーバー」と同じで、
行を右クリックして「削除」（確認あり）「書き出し…」、フッターのボタンから全件の書き出しと
取り込みができる。書き出すときはユーザー名とパスワードを含めるかどうかを選び（既定は含めない）、
取り込みで同じ接続に当たったら 1 件ずつ置き換えるか飛ばすかを尋ねる。

**SQL Server へは実際に接続する。**「接続をテスト」は本当にサーバーへ繋いで素性を読み、
「接続」が通るとメインウィンドウが開いて、データベース → スキーマ → テーブルをツリーで辿れる。

**PostgreSQL へも実際に接続する。**ドライバーを PostgreSQL に切り替えると、ポートと
データベースの既定が 5432 / `postgres` に変わる。「接続」が通るとメインウィンドウが開き、
データベース一覧が並ぶ。データベースを開けばスキーマ・テーブル・列・ストアド プロシージャ
（関数を含む）まで辿れる。この版ではそこまでで、セキュリティと編集グリッドはまだ書いていないので、
その枝もメニューも**出ない**（押してから断らないよう、セッションが自分にできることを申告している）。
SQL Server との違いは [connections.md](connections.md) を参照。

**データベース ユーザーは実際に読み書きする。**SSMS と同じく、データベースの下の
「セキュリティ → ユーザー」に一覧が並ぶ。「ユーザー」を右クリックして「新しいユーザー…」、
ユーザーを右クリックして「プロパティ」「削除」を選ぶと、SSMS の「データベース ユーザー」
ダイアログにあたる画面が開く。種類・ログイン名・既定のスキーマ・ロールのメンバーシップを
編集して OK を押すと、`CREATE USER` / `ALTER USER` / `DROP USER` が実行される。

**サーバー単位のログインも読み書きする。**SSMS と同じく、サーバーの下の
「セキュリティ → ログイン」に一覧が並ぶ。「ログイン」を右クリックして「新しいログイン…」、
ログインを右クリックして「プロパティ」「削除」を選ぶと、SSMS の「ログイン」ダイアログにあたる
画面が開く。認証方式・パスワードと規則（ポリシー・期限・次回変更）・既定のデータベース・
サーバー ロールのメンバーシップ・有効と無効を編集して OK を押すと、
`CREATE LOGIN` / `ALTER LOGIN` / `DROP LOGIN` が実行される。

**ロールとスキーマの所有権も読み書きする。**SSMS と同じく、データベースの下の
「セキュリティ → データベース ロール」と、サーバーの下の「セキュリティ → サーバー ロール」に
一覧が並ぶ。見出しを右クリックして「新しい…」、ロールを右クリックして「プロパティ」「削除」で
ダイアログが開き、ロール名・所有者・メンバー（サーバー ロールはメンバーシップ、データベース
ロールは所有するスキーマ）を編集できる。固定ロール（`db_owner` や `sysadmin`）は名前と所有者を
変えられないが、メンバーの出し入れはできる。スキーマは、データベースの下の「スキーマ」で
右クリックして所有者を付け替えられる（`CREATE SCHEMA` / `ALTER AUTHORIZATION` / `DROP SCHEMA`）。

**ユーザー マッピングとセキュリティ保護可能なリソースもダイアログのページとして開く。**
ログインのプロパティには「ユーザー マッピング」のページがあり、データベースごとにチェックを付けると
そのデータベースにユーザーが作られる（外せば消える）。ユーザー・ログイン・ロールのどのプロパティにも
「セキュリティ保護可能なリソース」のページがあり、リソースを足して権限を
「許可 / 許可の付与 / 拒否 / 指定なし」から選ぶと、`GRANT` / `DENY` / `REVOKE` が実行される。

**クエリも実際に実行する。**ツリーでテーブルかデータベースを右クリックして
「クエリを実行」（データベースなら「新しいクエリ」）を選ぶと、右の作業領域に**空の**エディタが開く。
決まるのは実行先のデータベースだけ。書いて「実行」（F5 / Ctrl+Enter）を押すと、
下の結果ペインにグリッドで結果が出る。

**クエリは複数のタブで開ける。**SSMS のクエリ ウィンドウと同じで、開くたびにタブが 1 枚増え、
文面も実行先も結果もタブごとに持つ。見出しは `SQLQuery1.sql` からの連番で、打ちかけの間は `*` が付く。
ツールバーの「新しいクエリ」（Ctrl+N）で足し、Ctrl+F4・中クリック・タブの `×` で閉じ、
Ctrl+Tab / Ctrl+Shift+Tab で行き来する。閉じたあとは直前に見ていたタブが前に出る。
ファイルへの保存はまだ無いので、閉じるときに確認はしない。

**エディタは色分け・補完・整形をする。**文面は字句へ切って色を当てるので、文字列やコメントの中の
`SELECT` は色が付かない。語を打ち始めるか `.` を打つと候補が出て、`FROM` のあとならスキーマとテーブル、
`o.` のように別名で修飾すればそのテーブルの列が並ぶ（カタログは接続ごとに覚えるので、2 回目からは
サーバーへ行かない）。「整形」（Ctrl+Shift+F）は句ごとに改行して予約語を大文字へ揃える。
整形は字句を並べ直すだけなので、文字列やコメントの中身と実行の結果は変わらない。

**ツリーは見出しごとに絞り込める。**SSMS のオブジェクト エクスプローラーと同じで、
見出し（データベース・スキーマ・テーブル・ストアド プロシージャ・ユーザー・ロール・ログイン）を
右クリックして「フィルター」→「フィルターの設定…」を選ぶと、条件にできるプロパティが 1 行ずつ並ぶ
ダイアログが開く。名前は「次を含む」「次を含まない」「次と等しい」「次と等しくない」、
作成日は「次より小さい」「次以上」「次の間」などから選ぶ。値を空にした行は条件にならず、
入れた条件は AND で重なる。大文字と小文字は区別しない。作成日を条件にできるのは、
エンジンから作成日を読んでいる見出し（データベース・テーブル・ストアド プロシージャ）だけで、
スキーマ・ユーザー・ロール・ログインは名前だけになる。

条件を決めると SSMS と同じくその見出しを読み直し、当てはまるものだけが並ぶ。掛かっている間は
見出しが「テーブル (フィルター適用)」になり、右の件数も絞り込んだあとの数になる。
元に戻すのは「フィルター」→「フィルターの削除」（掛かっていないときは押せない）。

**テーブルの中身は直に編集できる。**SSMS の「上位 200 行の編集」と同じで、テーブルを右クリックして
「先頭 100 行を編集」を選ぶと、作業領域に編集グリッドが開く。セルを押して打ち直し、Enter か
ほかのセルへ移ると、その 1 セルだけが `UPDATE` で書き戻る。保存ボタンは無い。
行の追加はいちばん下の新しい行（行番号が `*`）へ打ち込んで Enter、削除は行の右クリックから
（確認あり）。どちらも 1 行ずつ `INSERT` / `DELETE` を投げる。

デザインからの意図的な差分が 5 点ある。

- モックアップでは接続一覧の選択行に緑の接続中ドットが付くが、一覧の時点では接続していないので、
  代わりに読み取り専用で開く接続へ盾のアイコンを出している。
- `design/avalonia.md` はオブジェクトエクスプローラーに `TreeDataGrid` を挙げているが、
  今出している行（名前・件数・行数）は 1 行の中に収まるので `TreeView` で足りている。
  列として揃えたくなった時点で差し替える。
- `design/avalonia.md` は色分けに `AvaloniaEdit.TextMate` + `TextMateSharp.Grammars` を挙げているが、
  文法は自前の字句解析器（`SQLForge.Domain/Sql/SqlLexer.cs`）にしてある。TextMate はテーマごと
  自前の色を持ち込むので `Themes/Tokens.axaml` の `Syntax*Brush` に合わせ直す手間が要るうえ、
  解析結果を補完や整形から使い回せない（同じ文面を 2 通りに読む実装が並んでしまう）ため。
- モックアップはオブジェクトエクスプローラーの上に絞り込みの入力欄を置いているが、置いていない。
  絞り込みは SSMS に合わせて見出しごとの条件（右クリックの「フィルターの設定」）にしたので、
  ツリー全体に掛かる入力欄は意味が重なるうえ、どの見出しに何が掛かっているかが分からなくなるため。
- 結果グリッドも `TreeDataGrid` ではなく、`ListBox` に列幅を自前で配って組んでいる。
  行の仮想化は `ListBox` で足りていて、パッケージを 1 つ増やすほどの差がまだ無いため。
  列の並べ替えやリサイズを入れる時点で差し替える。`design/avalonia.md` の「列単位で
  フォントを切り替える」も入れていない（全部等幅で出し、日本語は OS のフォールバックに任せる）。

接続の使い方は [connections.md](connections.md)、クエリ実行とテーブル編集は [query-editing.md](query-editing.md) を参照。
